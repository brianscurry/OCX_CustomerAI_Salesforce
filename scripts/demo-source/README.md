# OCX Demo Salesforce Source Data

These utilities reconstruct the upstream-style Salesforce data used to
demonstrate OCX schema discovery and feature discovery.

## Purpose

OCXDemo was originally reverse-built from an anonymized OCX demo dataset.
That dataset itself was created from transformed customer source data.

The initial scratch org therefore contained a mixture of:

1. legitimate pre-model source data;
2. reconstructed demo data;
3. OCX-derived outcomes and model outputs.

This upgrade restores a more realistic representation of the data a
Salesforce connector could encounter before OCX feature engineering and
modeling.

## Eligible upstream domains

### Account / Profile

Examples:

- Industry
- Annual Revenue
- Number of Employees
- Geography
- Customer Since Date
- Customer Segment
- Region
- ACV
- Product
- Renewal profile

### Opportunity / Commercial

Examples:

- Stage
- Forecast Category
- Probability
- Amount
- Close Date
- ARR
- Annual Renewal
- Territory

OCXDemo currently represents a renewal-oriented Opportunity pipeline.

### Case / Support

The original demo support data came from ServiceNow.

For this Salesforce demo, the same source concepts are intentionally modeled
as data that could exist in Salesforce Service Cloud.

Examples:

- Status
- Priority / severity
- escalation
- time to resolution
- ageing of open cases
- support level
- root cause
- SLA violation
- product line
- support category

### Conversation metadata

Full conversations do not need to live in Salesforce.

The demo represents an architecture in which an external conversation
platform synchronizes lightweight activity metadata into Salesforce while
the full payload remains in its host database.

Existing Salesforce-side linkage includes:

- Task account/activity relationship
- Task activity date
- Task.OCX_Activity_ID__c
- Task.OCX_Channel__c

Task.OCX_Activity_ID__c is the demonstrated join key back to the full
conversation payload.

## Explicitly excluded as upstream feature evidence

The discovery system must not treat the following as Salesforce source
inputs simply because they physically exist in OCXDemo:

- OCX-generated NPS
- NPS class
- Journey SAT
- Driver SAT
- survey outcomes generated by OCX
- propensity / prediction outputs
- portfolio outputs
- expansion outputs
- downstream OCX model results
- OCX-generated Driver classifications where they leak the answer

These are downstream outcomes, labels, or model artifacts.

## Metadata deployment

Deploy the source metadata with:

    sf project deploy start \
      --target-org OCXDemo \
      --manifest manifest/ocx-demo-source-data-upgrade.xml \
      --test-level NoTestRun \
      --wait 30

Assign field access if required:

    sf org assign permset \
      --target-org OCXDemo \
      --name OCX_Demo_Source_Data

## Demo data reconstruction

Run in this order:

    scripts/demo-source/01_generate_source_seed.sh
    scripts/demo-source/02_refine_source_seed_v2.sh
    scripts/demo-source/03_refine_account_seed_v3.sh
    scripts/demo-source/04_apply_source_seed.sh preflight
    scripts/demo-source/04_apply_source_seed.sh apply
    scripts/demo-source/05_repair_case_escalation.sh

The apply utility creates pre-update rollback CSVs under .ocx/.

## Important design rule

The Salesforce demo contains raw source ingredients.

It intentionally does not create finished KPI fields merely to make ontology
discovery easier.

Example:

    Salesforce Case
      Time_to_Resolution_Days__c
      AccountId
            |
            v
    OCX Feature Engineering
      Average resolution time
      trailing six months
      by Account

## Current demo source shape

Account:

- 7,756 populated Accounts

Opportunity:

- 7,618 renewal-oriented Opportunities

Case:

- 2,996 support Cases
- closed Cases carry TTR
- open Cases carry ageing
- support/root-cause/product metadata populated
- escalation consistency enforced

Conversation:

- Salesforce provides activity/linkage metadata
- full payload remains in the Conversations DB
- OCX maintains the linkage between them
