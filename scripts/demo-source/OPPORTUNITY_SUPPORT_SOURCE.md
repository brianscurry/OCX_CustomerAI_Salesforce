# Bongo Opportunity + Support Source Reconstruction

## Purpose

This source reconstruction creates a credible pre-analytics Salesforce source
layer for the Customer AI discovery/retrieval demo.

It does not build generative CX models. The current demo milestone is:

`discover -> profile -> target -> retrieve -> display -> purge -> repeat`

## Authoritative Account population

The Bongo demo contains 7,755 authoritative Accounts.

Prototype-source Accounts that were intentionally removed from Bongo remain
removed and are never recreated.

## Opportunity source reconstruction

The existing Salesforce population contains 7,618 Opportunities.

The loader enriches all 7,618 existing records. It does not create new
Opportunities.

Source values are selected through the Bongo Account mapping. Renewal source
rows are ranked first and then by recency.

Source vocabulary is preserved in dedicated `Source_*` fields rather than
forcing it into Salesforce restricted fields such as StageName or Type.

Important source ingredients include source Opportunity ID, source stage, source
type, source forecast category, probability, age, ARR, annual renewal, average
ACV, renewal amounts, renewal due date, territory, CSM sentiment, engagement
type, owner role, lead source, business dates, region, and segment.

Prototype owner names are not loaded. Bongo demo identities are used.

## Support source reconstruction

Salesforce contains 2,996 total Cases:

- 2,994 linked to Accounts
- 2 org-only Cases with no AccountId and no source Case-number match

The two unlinked Cases are intentionally untouched.

A read-only diagnostic proved that the existing demo Case Numbers do not
preserve record-level lineage to `All_Support_Data.csv`: there were zero exact
Case-number matches.

Therefore the loader does not pretend there is Case-number lineage.

Instead it performs a controlled source overlay:

- a Support source row must belong to the same Bongo Account;
- a source row is used at most once;
- source rows are never borrowed from another Account;
- closed Salesforce Cases pair only with resolved source rows;
- open Salesforce Cases pair only with unresolved source rows;
- unmatched Cases remain untouched.

The verified load enriched 1,514 Cases:

- 603 closed Cases
- 911 open Cases

The remaining linked Cases were left untouched because no compatible
same-account source row was available.

## Product and PL

`Product` and `PL` are different source dimensions.

### Product

Support Product is normalized to the approved Bongo demo label and written to
`Case.Source_Product__c`.

Normalization includes:

- Composer variants -> Write Up
- Sign / DocuSign / Adobe Sign / EchoSign -> Sign Here
- Grid -> Matrix
- X-Author variants -> Write Up Enterprise
- Contracts variants -> Agreements
- CLM variants -> Contracta
- CPQ / Quote Generation / Turbo pricing/config/engines -> QuoteFlow
- Orchestrate / Conductor / Workflow -> Conductor
- Billing / Invoice / Revenue Management / Revenue Recognition -> Billing
- Collaborate -> Collab
- Digital Commerce -> Online Seller
- Order Management / Asset Based Ordering -> Order Pro
- Doc Gen / Mail Merge / Merge Server / Merge Service -> Write Up
- Approvals / Batch / Trigger -> Other
- any otherwise-unmapped Product containing `Community` -> Community
- every other otherwise-unmapped Product -> Other

### PL

`PL` is a separate product-line/category rollup and is not passed through the
Product-name mapping.

The observed source rollups include DocGen, Other, CPQ, and CLM.

`PL` is stored separately in `Case.Product_Line__c`.

## Source/output boundary

Raw source ingredients are not written into downstream Customer AI analytics
fields.

In particular:

- raw Account ACV -> `Account.Source_ACV__c`
- downstream Customer AI ACV -> `Account.OCX_ACV__c`
